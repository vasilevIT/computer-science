# Лабораторная работа №4 — пример выполнения

**Тема:** Анализ учебного набора данных с помощью SQL

**Предметная область:** сервис аренды велосипедов.

## 1. Описание набора данных

Для анализа используется база данных SQLite `lab04_example_bike_rentals.sqlite`, содержащая сведения о клиентах, велосипедах и арендах.

В базе три связанные таблицы:

| Таблица | Назначение | Количество записей |
|---|---|---:|
| `customers` | Клиенты сервиса | 12 |
| `bicycles` | Велосипеды, категории и тарифы | 8 |
| `rentals` | История аренды велосипедов | 24 |

Таблица `rentals` связана с `customers` через `customer_id`, а с `bicycles` через `bicycle_id`.

Для оценки выручки используется формула:

**Расчётная выручка = количество дней аренды × стоимость аренды за день.**

В базе отсутствуют сведения о фактических платежах, скидках и возвратах, поэтому полученные суммы являются расчётными.

## 3. Фильтрация и сортировка

### Вопрос 1. Какие аренды длились три дня и более?

Используем `WHERE` для отбора аренд и `ORDER BY` для сортировки по продолжительности.

```sql
SELECT
    r.id,
    c.full_name,
    b.model,
    r.rental_days,
    r.start_date
FROM rentals AS r
INNER JOIN customers AS c
    ON c.id = r.customer_id
INNER JOIN bicycles AS b
    ON b.id = r.bicycle_id
WHERE r.rental_days >= 3
ORDER BY r.rental_days DESC, r.id;
```

|---|---|---|---:|---|

| 6 | Дарья Соколова | Urban 100 | 4 | 2026-09-04 |
| 16 | Елена Волкова | City Lite | 4 | 2026-09-11 |
| 3 | Игорь Левин | City Lite | 3 | 2026-09-02 |
| 12 | Анна Орлова | Speed X | 3 | 2026-09-08 |
| 19 | Алексей Иванов | Trail Pro | 3 | 2026-09-13 |

**Вывод:** обнаружено 7 аренд продолжительностью от трёх дней. Самая длительная аренда составила 5 дней.

## 4. Агрегирование и группировка

### Вопрос 2. Какова общая и средняя продолжительность аренд?

Используем агрегатные функции `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.

```sql
SELECT
    COUNT(*) AS rental_count,
    SUM(rental_days) AS total_days,
    ROUND(AVG(rental_days), 2) AS avg_days,
    MIN(rental_days) AS min_days,
    MAX(rental_days) AS max_days
FROM rentals;
```

**Результат:**

| Количество аренд | Всего дней | Среднее | Минимум | Максимум |
|---:|---:|---:|---:|---:|
| 24 | 51 | 2.13 | 1 | 5 |

**Вывод:** всего совершено 24 аренды общей продолжительностью 51 день. Средняя аренда длится около двух дней.

### Вопрос 3. Как распределяется расчётная выручка по категориям?

Объединим сведения об арендах и велосипедах, затем сгруппируем по категориям.

```sql
SELECT
    b.category,
    COUNT(*) AS rental_count,
    SUM(r.rental_days) AS total_days,
    SUM(r.rental_days * b.daily_price)
        AS estimated_revenue
FROM rentals AS r
INNER JOIN bicycles AS b
    ON b.id = r.bicycle_id
GROUP BY b.category
ORDER BY estimated_revenue DESC;
```

**Результат:**

| Категория | Количество аренд | Дней аренды | Расчётная выручка, ₽ |
|---|---:|---:|---:|
| Горный | 9 | 16 | 18 400 |
| Городской | 9 | 24 | 16 100 |
| Шоссейный | 6 | 11 | 15 100 |

**Вывод:** наибольшую расчётную выручку обеспечили горные велосипеды — 18 400 рублей. При этом городские велосипеды лидируют по суммарной продолжительности аренды.

### Вопрос 4. Какие категории принесли более 10 000 рублей?

Для фильтрации сгруппированных результатов используем `HAVING`.

```sql
SELECT
    b.category,
    SUM(r.rental_days * b.daily_price)
        AS estimated_revenue
FROM rentals AS r
INNER JOIN bicycles AS b
    ON b.id = r.bicycle_id
GROUP BY b.category
HAVING SUM(r.rental_days * b.daily_price) > 10000
ORDER BY estimated_revenue DESC;
```

**Результат:**

| Категория | Расчётная выручка, ₽ |
|---|---:|
| Горный | 18 400 |
| Городской | 16 100 |
| Шоссейный | 15 100 |

**Вывод:** все три категории превысили порог в 10 000 рублей. `HAVING` позволяет отбирать категории по результату агрегирования.

## 5. Анализ связанных таблиц

### Вопрос 5. Какие велосипеды арендовали клиенты и сколько стоила каждая аренда?

Для получения данных сразу из трёх таблиц используем `INNER JOIN`.

```sql
SELECT
    r.id,
    c.full_name,
    b.model,
    r.rental_days,

INNER JOIN customers AS c
```

### Вопрос 6. Какие клиенты ещё не пользовались сервисом?

Используем `LEFT JOIN`, чтобы сохранить в результате всех клиентов, включая тех, у кого отсутствуют аренды.

```sql
SELECT
    c.id,
    c.full_name,
    c.city
FROM customers AS c
LEFT JOIN rentals AS r
    ON r.customer_id = c.id
WHERE r.id IS NULL
ORDER BY c.id;
```

**Результат:**

| ID | Клиент | Город |
|---|---|---|
| 11 | Вера Зайцева | Самара |
| 12 | Максим Крылов | Уфа |

**Вывод:** два зарегистрированных клиента ещё не совершали аренды.

### Вопрос 7. Какие велосипеды ни разу не арендовали?

Аналогично используем `LEFT JOIN`, чтобы найти велосипеды без связанных записей в таблице `rentals`.

```sql
SELECT
    b.id,
    b.model,
    b.category
FROM bicycles AS b
LEFT JOIN rentals AS r
    ON r.bicycle_id = b.id
WHERE r.id IS NULL
ORDER BY b.id;
```

**Результат:**

| ID | Модель | Категория |
|---|---|---|
| 7 | Commuter | Городской |
| 8 | Trail Mini | Горный |

**Вывод:** два велосипеда пока не использовались для аренды. Это может быть поводом изучить спрос на данные модели.

## 6. Проверка корректности

Проверим, существуют ли аренды, у которых отсутствует связанный клиент или велосипед.

```sql
SELECT
    COUNT(*) AS orphan_rentals
FROM rentals AS r
LEFT JOIN customers AS c
    ON c.id = r.customer_id
LEFT JOIN bicycles AS b
    ON b.id = r.bicycle_id
WHERE c.id IS NULL
   OR b.id IS NULL;
```

**Результат:**

| orphan_rentals |
|---:|
| 0 |

**Вывод:** все 24 аренды связаны с существующими клиентами и велосипедами. Нарушений ссылочной целостности в проверенных данных не обнаружено.

Дополнительно сопоставим результаты агрегирования:

- Суммарное количество аренд по категориям: 9 + 9 + 6 = 24.
- Суммарное количество дней по категориям: 16 + 24 + 11 = 51.
- Общая расчётная выручка: 18 400 + 16 100 + 15 100 = 49 600 рублей.

Количество аренд и дней совпадает с результатами общего агрегирующего запроса.
